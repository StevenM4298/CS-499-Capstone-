Enhancement 1

For enhancement one, I chose to adapt artifact one, the weight loss tracking android studio application developed in CS 360 – Mobile Architect and Programming. The application is designed to allow a user to login or register if no previous account was created. Once authenticated, a homepage is presented that shows the current weight (if entered) as well as an option for adding a new entry, viewing current progress represented in the progress bar, and setting a new goal. Additionally, a calendar button is provided to access the calendar grid showing all previous weight entries and the date that they were entered.

This artifact demonstrates the ability to code in Java, as well as create a functional user interface. The greater demonstration of skills is the ability to join these two components to form a seamless flow for a user to interact with. Furthermore, category one is titled “Software Engineering and Design” which presented a great opportunity to enhance this application’s architecture. In its original state, the application had a login and homepage class that were handling all the user interface mechanics including buttons and display, in addition to all the math calculations and logic. Creating two new controller classes to take over the calculations demonstrates an ability to not only enhance an application but think differently about how a program functions. In addition, I demonstrated the ability to create a cohesive project that handles various elements, methods and classes that all work together. Many of the components interact with other pages, such as the calendar page needing to take the stored weight in the JSON list to accurately reflect what the user has entered. I do believe that these criteria resolve the course outcomes that relate to this artifact and enhancement.

The biggest challenge was linking all the java files and correcting the communication once the enhancements were made. By creating these additional classes to handle the calculations and fixing the error in the current weight calculation, this created a mostly different architecture that needed re-working to allow them to communicate with each other. I learned that sometimes there may be a method that works best for one area, but not for another. Therefore, it is important to understand how to strike a balance that works best for the overall program or application.

Enhancement 2

For enhancement two, I chose to perform an enhancement of the Course Planner C++ program that was originally made for CS 300. This program presents the user with a menu to load data from a course list file, and once loaded, print a list of all courses, print a specific course, or exit the program. The program parses each line of the file loaded and stores the Course ID, name and prerequisites.

As the 2nd category for enhancement is titled “Algorithms and Data Structures”, I decided to enhance this artifact by upgrading the simple unordered_map that is currently built into the program and replace it with a node based linked list. This will demonstrate my ability to work with different types of data structures, as well as modify existing project architecture while not compromising the original functionality.

Some of the aspects of the new code include node structure to establish a new node to hold a single course’s information, then incorporate pointers to connect all the nodes in a chain, that the program can then start from the beginning to search for specific data or print in alphanumerical order. In addition, I included a crucial element to the overall system architecture that deallocates memory in the list. Without this “clearList” function, each time a user selected to load data, the original data would remain in the memory. This data builds up and could result in memory leaks. This could slow the memory and eventually crash the program. By calling clearList(head), we are clearing out the data before loading new data.

I do believe that I am continuing to demonstrate the ability to satisfy the course outcomes with this enhancement. This enhancement required an ability to identify an area for improvement regarding data structures, design, build and finalize the improvement. As the overall architecture has been reconfigured with the addition of the linked list data structure, I am prepared to begin the final enhancement. This course planner program, artifact two, will also be used to satisfy enhancement three for databases. The courser planner will be upgraded to include authentication methods to verify a standard user or an admin via an SQLite database. If the user is an admin, CRUD operations will be given to modify course data.
